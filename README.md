**Интернет-магазин спортивной одежды и аксессуаров.**

Проект представляет собой полнофункциональный веб-сайт для продажи спортивных товаров с возможностью фильтрации, корзиной, избранным, оформлением заказов и админ-панелью.

## Технологический стек

### Бэкенд
- **Go** (1.25+) - серверная логика
- **gorilla/mux** - маршрутизация
- **pgx** - драйвер для PostgreSQL (пул соединений)
- **JWT** - аутентификация (в httpOnly cookie)
- **bcrypt** - хэширование паролей
- **reCAPTCHA v3** - защита от ботов
- **ulule/limiter** - rate limiting (in-memory, планируется переход на Redis)
- **slog** - структурированное логирование

### Фронтенд
- **Vue 3** (Composition API)
- **Vite** - сборка
- **Pinia** - управление состоянием
- **Vue Router** - маршрутизация
- **vue-i18n** - интернационализация (ru/en)
- **Axios** - HTTP-клиент (с CSRF-защитой)
- **Swiper** - карусели
- **Perfect Scrollbar** - кастомный скролл
- **Sass/SCSS** - стилизация

### База данных
- **PostgreSQL** - основная БД

## Основные API-эндпоинты
### Публичные (без авторизации)
- `GET /api/items` - каталог с фильтрацией и пагинацией
- `GET /api/items/{uniqueId}` - информация о товаре
- `GET /api/items/{uniqueId}/similar` - похожие товары (до 4)
- `GET /api/main-page/new` - данные баннера на главной
- `GET /api/filters` - все доступные фильтры (бренды, категории, цвета и т.д.)
- `GET /api/exchange-rate` - текущий курс CNY/RUB

### Аутентификация
- `POST /api/auth/register` - регистрация (требуется captcha)
- `POST /api/auth/login` - вход (лимит 2 запроса/мин)
- `GET /api/auth/me` - данные текущего пользователя

### Профиль пользователя (авторизация)
- `PUT /api/user/profile` - обновление имени, email, пароля
- `DELETE /api/user/profile` - удаление аккаунта (soft delete)

### Корзина (авторизация)
- `GET /api/user/cart` - список товаров в корзине
- `POST /api/user/cart/{uniqueId}` - добавление товара (размер, количество)
- `PUT /api/user/cart/{uniqueId}` - изменение количества
- `DELETE /api/user/cart/{uniqueId}?size=...` - удаление позиции

### Избранное (авторизация)
- `GET /api/user/favourites` - список uniqueId избранных товаров
- `GET /api/user/favourites/items` - детальная информация по избранным товарам
- `POST /api/user/favourites/{uniqueId}` - добавить в избранное
- `DELETE /api/user/favourites/{uniqueId}` - удалить из избранного

## Безопасность

Проект реализует многоуровневую защиту:

### Аутентификация
- JWT-токены хранятся в **httpOnly cookie**, недоступных для JavaScript (защита от XSS).
- Пароли хэшируются с помощью **bcrypt** (стоимость 10).
- Токен живёт **24 часа**.

### CSRF-защита
Используется механизм **двойной отправки токена**:
- При **GET-запросе** устанавливается cookie csrf_token.
- При **не-GET запросах** фронт читает этот токен и передаёт в заголовке X-CSRF-Token.
- Сервер проверяет совпадение через **hmac.Equal** (защита от timing-атак).

### Rate Limiting
- Глобальный лимит: **100 запросов/мин** на всё приложение.
- Специфичный лимит на **/auth/login** и **/auth/register**: 2 запроса/мин (защита от брутфорса).

### reCAPTCHA v3
- Используется на **регистрации** и **создании заказа**.
- Токен верифицируется на сервере через **Google API**.

### Заголовки безопасности
- X-Content-Type-Options: nosniff
- X-Frame-Options: DENY
- Referrer-Policy: strict-origin-when-cross-origin
- Strict-Transport-Security (при HTTPS)
- Content-Security-Policy (разрешены только свои ресурсы, CDN и Google)

### Защита от SQL-инъекций
- Во всех запросах к БД используются подготовленные выражения с параметрами ($1, $2).

### Защита от Path Traversal
- При удалении файлов проверяется, что путь не содержит .. и опасных символов.

## Масштабирование и планы по улучшению
В текущей версии есть ограничения, которые необходимо устранить для высоких нагрузок:

### Текущие ограничения
- **Кеш in-memory** - не синхронизируется между экземплярами.
- **Rate limiting in-memory** - не работает при горизонтальном масштабировании.
- **Файлы хранятся локально** - не подходит для распределённой среды.
- **Нет рефреш-токена** - сессия привязана к одному токену.

### Планируемые улучшения
1. Переход на Redis для:
    - Кеширования данных (вместо DBCache).
    - Хранения rate limiting (вместо in-memory).
    - Возможно, хранения сессий (если добавим рефреш-токены).
2. Использование S3-совместимого хранилища для загруженных файлов.
3. Добавление рефреш-токена для продления сессии без повторного ввода пароля.
4. Настройка пула соединений с БД (макс. количество соединений, время жизни).
5. Добавление таймаутов на запросы к БД через контекст.
6. Оптимизация CSP – убрать unsafe-inline через nonce.
7. Покрытие кода тестами (интеграционные тесты для критических сценариев).

## Возможные проблемы и их решение

| Проблема | Решение |
|:---:|:---:|
| При перезапуске сервера все JWT-токены становятся невалидными | Убедитесь, что в .env задан фиксированный JWT_SECRET. |
| Забаненный пользователь может изменять корзину | Добавить middleware, проверяющий `deleted_at` для всех авторизованных запросов. |
| Видеофайлы большого размера могут перегрузить сервер | Установить лимит на размер загружаемых файлов (например, 20 МБ) и ограничить время обработки. |
| В админке не работает пагинация для товаров | Реализовать пагинацию в `AdminItemsHandler` (сейчас все товары из кеша). |
| Нет документации по миграциям БД | Создать папку migrations/ с SQL-скриптами для воспроизведения схемы. |
